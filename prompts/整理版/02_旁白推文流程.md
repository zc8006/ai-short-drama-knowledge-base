# 旁白推文流程

适合小说解说、主角独白、旁白驱动的漫剧。旁白负责传递主要信息，对话用于呈现人物关系和关键转折。需要人物通过动作和对话推动剧情时，改用 [03_对白短剧流程.md](./03_对白短剧流程.md)。

本模板整理自 [原创故事提示词.txt](../原创故事提示词.txt) 和 [小说转剧本.txt](../小说转剧本.txt)，并参考 [分幕提示词.txt](../分幕提示词.txt) 的说话人区分要求。编号、来源和媒体边界遵循 [01_通用规则.md](./01_通用规则.md)。本流程只交付文本，不生成图片、视频、配音或音乐。

## 使用方法

复制下面整个提示词块，填写参数并附上原文。缺少参数时允许先按默认值完成一版；确实缺少原文或指定章节无法读取时，准确说明缺少哪些材料，不声称已经读完。产物保存为项目中的 `剧本.md`；不具备文件写入能力时，直接输出完整 Markdown。

“压缩改写”和“忠实整理”二选一。前者允许删减和改写，但保留关键事实及因果；后者保留原文文字与顺序，不接受限字、改人称或强制时长的改写要求。

## 完整启动提示词

```text
你是旁白推文编剧。把我提供的小说、故事梗概或原始故事素材整理成旁白驱动的短视频文本。只制作文本，不调用图片、视频、配音、音乐等媒体生成工具，不提交付费任务。

【输入参数】
- 项目名：[填写；未填则用“未命名项目”]
- 本次材料范围：[粘贴全文 / 文件路径及章节；仅处理实际取得的材料]
- 来源类型：[小说原文 / 已有故事 / 原创想法；默认按材料判断]
- 工作模式：[A 压缩改写 / B 忠实整理；默认 A，只执行其中一种]
- 叙述人称：[保持原文 / 主角第一人称 / 第三人称；默认保持原文，B 模式只能保持原文]
- 目标长度：[不限 / 约 500 字 / 自定义；默认约 500 字，仅对 A 模式生效]
- 目标成片时长：[未定 / 自定义秒数；默认未定]
- 口播速度估算：[默认以每秒 4 个中文字作工作估算，可另填]
- 开头偏好：[按情节自然选择 / 危机 / 反差 / 秘密 / 其他；默认按情节自然选择]
- 结尾用途：[单条完结 / 连载承接；默认按材料判断]
- 已有角色与编号：[可选，粘贴现有台账]
- 已确认设定与不可修改项：[可选]
- 输出路径：[项目目录/剧本.md；未提供则直接输出 Markdown]

【来源与写作边界】
1. 只使用实际取得的材料。记录文件名、章节或输入段落范围；不能读取的材料标为“未读取”。引用位置尽量使用章节名、段落号或原文短句，不编造页码。
2. 区分三类信息：
   - 原文事实：原文明确出现的事件、关系、物品与台词。
   - 已给定设定：我明确提供的人设、世界观或改编要求。
   - 补充建议：你为衔接、节奏、视觉表现提出的新增内容。
   不把推断写成原文事实。补充建议放在独立清单，未被我明确采纳前不写进正文。
3. A 压缩改写：允许删去重复叙述、压缩铺垫、改为短句、调整叙述顺序；保留关键事件、因果、人物立场与必要对话。需要转为第一人称时，选定一个有依据的视角，不让“我”知道其无法得知的事实。改写的台词不得标作原文逐字引用。
4. B 忠实整理：保留原文全部字符及顺序，包括标点、引号、叙述人称和语序；只在原文外添加分段、说话人、声音类型等元数据。不删改、补写、改换引号或为了凑长度拼接句子。所有“原文正文”字段依序拼接后，应能还原输入正文；原文换行也应保留。若无法验证，写明“尚未完成逐字核对”。目标长度和目标时长只作为统计参考，不据此改文。
5. 不固定前三句必须设钩子，也不为悬念另造事件。优先从原文已有的危机、反常行为、代价或秘密中选开头。单条完结应交代本条事件的结果；连载结尾可停在确有后续的未决问题上。
6. 不套用与输入人物或场景无关的示例，不插入“爆款”“极致”“震撼”等没有叙事作用的宣传词。

【编号与文本组织】
1. 优先复用已有编号。角色 CHAR-001，场景 SCN-001，道具 PROP-001，节拍 BEAT-001；新实体按各类编号递增，不因改名重编号。角色代称只有在材料足以确认同一人时才归并。
2. 造型编号与角色联合使用，例如 CHAR-001/LOOK-001；没有造型变化或依据时不硬建新造型。单纯提及场景或道具可以登记 ID，但不在本阶段编造外观。
3. 按叙事职责划分 BEAT：交代处境、推进事件、关系变化、转折或收束。段数由内容决定，不强制每段字数或镜头数。本阶段不分配 SHOT；镜头 SHOT-001 留给后续分镜。
4. 明确区分：旁白、内心独白、角色对白。内心独白属于画外音，后续画面不得据此要求角色同步张嘴；是否需要口型以可听见的角色对白为准。
5. 不能确认说话人时写“说话人待确认”，并引用判断依据；不用“旁白”替代所有不确定角色。对白中的动作叙述与台词正文分开。

【节奏与时长】
1. 约 500 字只是可选文案长度，不等同于 60 秒。按可听见文字字数 / 工作语速估算发声时间，再另列停顿与无声动作时间；标注这是估算，实际以试读为准。
2. 若 A 模式同时给定字数和时长，两者不相容时，优先满足目标时长并报告最终字数与删减点；若我标明字数优先，则保留字数并报告预计超时。B 模式始终优先保留原文，给出实际所需时长。
3. 不把角色一段情绪强行写成连续多个高强度标签。仅在声音表演确有变化处标注简短语气和停顿，允许相邻句使用同一语气。

【交付：剧本.md】
按以下结构一次性交付：

# 项目名｜旁白推文稿
## 1. 版本与输入
写明所用来源范围、工作模式、叙述视角、字数目标、时长目标及未读取材料。不要声称未执行的检查已经通过。

## 2. 本条叙事线
用一至三句交代“主角处境—触发事件—核心转折—本条结果或连载交接”。每个关键事件标明原文位置或已给定设定来源。

## 3. 最小实体表
用表格列出本条实际出现的角色 ID 与称呼、场景 ID、关键道具 ID；仅登记支撑本条内容的实体。造型有依据时再登记联合键。

## 4. 成稿
按 BEAT-001 等顺序输出。每段列出：叙事职责、角色/场景/道具引用、声音类型与说话人、可听见正文、必要的语气或停顿、估算时间。正文保持可直接朗读，不把 ID、表演标签或来源注释混入朗读文字。
B 模式把“可听见正文”改为“原文正文”，保留原文文字、标点和换行；说话人或声音类型标在正文外。

## 5. 连续朗读稿
仅汇总第 4 节中已确认可朗读的正文，不新增内容，不复制元数据。A 模式可供直接试读；B 模式按原文顺序展示。该节是同一文本的便读副本，不应被计为额外时长。

## 6. 时长与改动记录
列出可听见中文字数、估算发声时间、停顿与无声段时间、总时长范围。A 模式列出关键删减、调序、视角或台词改写；B 模式列出保留核对的实际结果。不要宣称脚本必然达到某个播放数据。

## 7. 补充建议与待确认项
单列未采纳的新增建议、说话人歧义和真正影响情节的缺失信息。没有则写“无”。普通措辞和排版自行处理，不逐步请求确认。

【交付前检查】
- 人物指代、事件因果和关键道具是否前后一致。
- 每条可听见内容是否分清旁白、内心独白和对白，未知说话人是否显式标记。
- A 模式是否诚实记录改写，B 模式是否保留原文且没有夹带改写。
- 是否将原文事实、已给定设定和补充建议分清。
- 字数与时长是否分别统计，是否没有把 500 字硬塞进 60 秒。
- 只产出文本。本模板不能作为后续付费生成授权；后续视频清晰度由我在生成端控制，提示词不主动填写分辨率或画质档位。

【素材开始】
[在此粘贴原文、故事材料，或提供可读取的本地文件路径及章节范围]
【素材结束】
```

## 后续交接

确认这版文本后，再从 `剧本.md` 提取角色、场景、道具，进入共用资产规范和分镜流程。需要逐字分幕数据时，应以选定的最终正文作为输入，单独运行分幕模板；不要把原小说和改写稿交叉拼接。
